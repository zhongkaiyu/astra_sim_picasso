# GQA 单层 Seq Scaling 对比报告：Block2x2 拓扑优化 vs 原版 vs TP16

> **生成时间**: 2026-03-04
> **设备**: HBM4 | **物理拓扑**: Mesh2D 4×4 | **逻辑路由**: OneRing
> **模型参数**: Qwen (head=64, kvhead=4, dmodel=4096, head_dim=128, batch=64)
> **并行配置**: tp_h=4, tp_s=4 (16 GPUs)
> **测试范围**: Seq = 1024, 2048, 4096, 8192, 16384, 32768, 65536 (单层 GQA, num_stacks=1)
> **前置报告**: [`20260303_gqa_seq_scaling_comparison.md`](20260303_gqa_seq_scaling_comparison.md)

---

## 1. 实验目的

前期 seq scaling 报告在 Baseline、HMP、TP16 三种策略间做了系统对比。本实验引入 **block2x2 rank remap** 拓扑优化，测试其在序列长度 1k→64k 范围下对 Baseline 和 HMP 策略的影响，并与 TP16 做横向对比。

### 1.1 Block2x2 原理回顾

Block2x2 通过 `main.py --rank_remap block2x2` 重映射逻辑 rank 到物理 GPU，改变通信组在 Mesh2D 上的物理布局：

| 维度 | 原版布局 | Block2x2 布局 | 效果 |
|------|----------|---------------|------|
| g17 (tp_h) | 同行 4 GPU | 棋盘 (max 2 hop) | max hop 3→2，但平均 hop 1.5→2.0 |
| g21 (tp_s) | 同列 4 GPU | 2×2 block (max 1 hop) | max hop 3→1 (**最优**) |

g21 承载更多通信量（AllReduce + AllGather），因此 block2x2 对 g21 的 1-hop 优化是核心收益点。

### 1.2 策略对比矩阵

| 策略 | CacheSeq | 通信操作 (单层 GQA) | Block2x2 影响 |
|------|----------|---------------------|---------------|
| **Baseline** | ceil(Seq/4) | 3 ops: AR(g21) + AR(g17) + AG(g21) | comm 减少 1,212 ns |
| **Baseline_block2x2** | ceil(Seq/4) | 同上，路由更短 | 对照组 |
| **HMP** | ceil(Seq/4) | 0 ops (终端节点优化) | **无影响** |
| **HMP_block2x2** | ceil(Seq/4) | 同上 | 与 HMP 完全相同 |
| **TP16** | Seq - 1 | 2 ops: AR(g17) + AR(g21) | 未测试 (16-GPU ring) |

### 2.3 通信时间 (ns)

| 策略 | 通信时间 | 操作数 | 随 Seq 变化 |
|------|------:|:---:|:---:|
| **HMP / HMP_block2x2** | 0 | 0 ops | N/A |
| **Baseline_block2x2** | 18,265 | 3 ops | 恒定 |
| **Baseline** | 19,477 | 3 ops | 恒定 |
| **TP16** | 47,480 | 2 ops | 恒定 |

### 2.4 通信时间逐操作对比 (Baseline vs Baseline_block2x2)

| # | 节点 | 类型 | Group | 原版 (ns) | Block2x2 (ns) | 差值 |
|:-:|------|:----:|:-----:|------:|------:|------:|
| 1 | `mha.attn` | ALL_REDUCE | g21 (tp_s) | 7,760 | 4,340 | **-3,420** |
| 2 | `mha.o` | ALL_REDUCE | g17 (tp_h) | 7,760 | 10,580 | **+2,820** |
| 3 | `mha.o` | ALL_GATHER | g21 (tp_s) | 3,957 | 3,345 | **-612** |
| | **合计** | | | **19,477** | **18,265** | **-1,212** |

**分析**：
- **g21 (tp_s) 改善**：block2x2 将 g21 从同列布局 (max 3 hop) 改为 2×2 block (max 1 hop)，AR 延迟 **-44%**，AG 延迟 **-15%**
- **g17 (tp_h) 退化**：block2x2 将 g17 从同行布局改为棋盘布局 (max 2 hop)，AR 延迟 **+36%**
- **净收益 1,212 ns**：g21 的改善 (4,032 ns) 大于 g17 的退化 (2,820 ns)，因为 g21 的 3-hop 回程瓶颈被完全消除

## 3. 分析

### 3.1 Block2x2 对 Wall Time 的影响

Block2x2 对 Baseline 产生 **恒定 1,212 ns** 的 wall time 改善（= 通信时间减少量）。由于改善量固定而 wall time 随 Seq 线性增长，百分比改善随 Seq 递减：

| Seq | Wall 改善 (ns) | Wall 改善 (%) | 通信占 Wall 比例 |
|------:|------:|------:|------:|
| 1,024 | 1,212 | 2.41% | 38.7% → 37.3% |
| 4,096 | 1,212 | 1.76% | 28.3% → 27.1% |
| 16,384 | 1,212 | 0.85% | 13.7% → 12.9% |
| 65,536 | 1,212 | 0.28% | 4.4% → 4.2% |

**结论**：Block2x2 的绝对收益不变，但随序列增长被计算时间稀释，长序列下几乎可忽略。

### 3.2 HMP 对 Block2x2 完全免疫

HMP 在单层 GQA 模式下通信时间为 0（output `o` 是终端节点，无后续消费者，通信被优化跳过）。因此 block2x2 rank remap 对 HMP **毫无影响**，所有指标完全一致。

> **注意**：多层 E2E 模式下，HMP 的 `o` 有后续依赖（残差连接），通信会恢复。此时 block2x2 对 HMP 可能产生与 Baseline 类似的效果——但 E2E 94 层实验（见 `mesh2d-topology-findings` rule）显示 block2x2 在密集通信场景下因链路竞争反而导致 comm +17~20%。

### 3.3 五策略性能排名

| Seq 范围 | 最优 | 次优 | 第三 | 第四 | 最差 |
|----------|:----:|:----:|:----:|:----:|:----:|
| 全部 (1k–64k) | **HMP** | HMP_b2x2 (=HMP) | BL_b2x2 | Baseline | **TP16** |

在本实验的所有序列长度下，排名完全固定：
1. **HMP = HMP_block2x2**：零通信 + 适中计算量，始终最优
2. **BL_block2x2**：比 Baseline 快 1,212 ns
3. **Baseline**：通信 19,477 ns（恒定）
4. **TP16**：通信最高 (47,480 ns) + 计算增长最快 (10.9 ns/Seq vs 6.0)

### 3.4 TP16 的双重劣势

TP16 在本实验中 **全面落后**，因其同时承受两个惩罚：

| 惩罚维度 | TP16 | Baseline | 差异原因 |
|----------|------|----------|----------|
| **通信** | 47,480 ns (固定) | 19,477 ns (固定) | 16-GPU OneRing 在 Mesh2D 上有 4-hop 跨行段 |
| **计算斜率** | 10.92 ns/Seq | 6.01 ns/Seq | CacheSeq=Seq-1 vs ceil(Seq/4)，KV cache 4× 更大 |

TP16 的 wall time 在 sl1024 已比 HMP 高 58%，到 sl65536 扩大到 79%。

> **注意**：本实验的 TP16 使用 16-GPU OneRing 环路径 (comm=47,480 ns)，与前置报告 `20260303_gqa_seq_scaling_comparison.md` 中 TP16 使用 4-GPU 分组路由 (comm=15,810 ns) **不同**。两份报告的 TP16 数据不可直接对比。前置报告的 TP16 在短序列下优于 Baseline，而本报告的 TP16 全面落后，差异完全来自通信路由配置。

### 3.5 线性增长验证

| 策略 | 斜率 a (ns/Seq) | 截距 b (ns) | 通信 (ns) |
|------|------:|------:|------:|
| HMP / HMP_b2x2 | 6.0075 | 38,055 | 0 |
| Baseline_b2x2 | 6.0075 | 42,898 | 18,265 |
| Baseline | 6.0075 | 44,110 | 19,477 |
| TP16 | 10.9227 | 58,666 | 47,480 |

- HMP 和 Baseline 斜率完全相同 (6.0075 ns/Seq)，因为 CacheSeq 定义一致 (ceil(Seq/4))
- Block2x2 仅改变截距 (44,110 → 42,898 = -1,212)，不影响斜率
- TP16 斜率为 HMP/BL 的 **1.82×**，因 CacheSeq = Seq-1（完整 KV cache）

## 4. 累积 Decode 延迟分析

自回归解码中，每步 cache 长度递增。生成 N 个 token 的总延迟 = Σ_{t=1}^{N} Latency(Seq=t)。

### 4.1 累积公式

Total(N) = a × N×(N+1)/2 + b × N

| 策略 | a | b | Total(1024) | Total(4096) | Total(65536) |
|------|----:|----:|------:|------:|------:|
| HMP | 6.0075 | 38,055 | 42.11 ms | 206.28 ms | 15,395 ms |
| BL_b2x2 | 6.0075 | 42,898 | 47.07 ms | 226.04 ms | 17,568 ms |
| Baseline | 6.0075 | 44,110 | 48.32 ms | 231.00 ms | 17,647 ms |
| TP16 | 10.9227 | 58,666 | 65.79 ms | 331.70 ms | 27,259 ms |

### 4.2 Block2x2 累积收益

| 生成 N tokens | BL 累积 (ms) | BL_b2x2 累积 (ms) | 节省 (ms) | 节省 (%) |
|------:|------:|------:|------:|------:|
| 1,024 | 48.32 | 47.07 | 1.24 | 2.6% |
| 4,096 | 231.00 | 226.04 | 4.97 | 2.1% |
| 16,384 | 2,649.0 | 2,629.1 | 19.9 | 0.7% |
| 65,536 | 17,647 | 17,568 | 79.3 | 0.4% |

累积节省 = 1,212 ns × N / 10⁶ ms。在 65k token 生成任务中节省 ~79 ms，占比仅 0.4%。

## 5. 与 E2E 多层实验的关联

### 5.1 单层 vs 多层 Block2x2 效果对比

| 场景 | Block2x2 对 comm 的影响 | 原因 |
|------|:---:|------|
| **单层 GQA** (本报告) | **-6.2%** (1,212 ns) | g21 的 3-hop 回程消除；无拥塞（通信串行） |
| **E2E 94 层** (见 topology rule) | **+17~20%** | g17 棋盘布局导致不同组的 2-hop 路径在中间节点交叉，链路竞争严重 |

### 5.2 根本原因

Block2x2 的收益/代价分布不均：

| 通信组 | 原版 → Block2x2 | 单次延迟变化 | 总链路占用变化 |
|--------|------------------|:-----------:|:------------:|
| g21 (tp_s) | 同列 → 2×2 block | **改善** (max 3→1 hop) | -33% (24→16) |
| g17 (tp_h) | 同行 → 棋盘 | **退化** (max 3→2 hop，avg 1.5→2.0) | +33% (24→32) |

单层场景下 g21 改善 > g17 退化，整体正收益。但多层 E2E 场景中：
- g17 棋盘布局的 2-hop 路径在中间节点**跨组交叉**（不同 g17 组共享物理链路）
- 94 层密集通信放大了这种空间竞争
- 总链路占用虽然不变 (48 = 16+32 = 24+24)，但分布更不均匀

## 6. 结论

### 6.1 Block2x2 在单层 GQA 的评估

| 指标 | 评估 |
|------|------|
| 通信改善 | **有效**：-6.2% (1,212 ns)，通过消除 g21 的 3-hop 回程实现 |
| Wall time 改善 | **微弱**：-0.3%~-2.4%（被计算时间稀释） |
| HMP 策略影响 | **无**：单层零通信 |
| 累积 decode 收益 | **可忽略**：65k tokens 仅节省 79 ms / 17.6s |
| 推荐 | 单层无拥塞场景下 block2x2 略有收益，但不显著 |

### 6.2 策略推荐

| 场景 | 推荐策略 | 理由 |
|------|----------|------|
| 单层 GQA，任意 Seq | **HMP** | 零通信 + 适中计算量 |
| 单层 GQA，需要 Baseline | **BL_block2x2** | 比原版快 1,212 ns（微弱改善） |
| E2E 多层，密集通信 | **原版行/列布局** | Block2x2 因链路竞争反而退化 |
| 短输出 decode (≤4k tokens) | 根据 E2E 交叉点决定 | 需结合 E2E 拥塞数据评估 |

### 6.3 TP16 评估

本实验中 TP16 使用 16-GPU OneRing（comm=47,480 ns），在所有序列长度下均为最差策略。其 wall time 在短序列时比 HMP 高 58%，长序列时差距扩大至 79%。TP16 的劣势来源于：
1. **通信路由**：16-GPU OneRing 在 4×4 Mesh2D 上有 4-hop 跨行段，comm 是 Baseline 的 2.44×
2. **KV cache 规模**：CacheSeq = Seq-1 (vs ceil(Seq/4))，计算斜率为 HMP/BL 的 1.82×
