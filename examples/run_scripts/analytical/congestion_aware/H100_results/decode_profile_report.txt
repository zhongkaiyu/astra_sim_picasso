║  每阶段详细解释                                                                                            ║
╚══════════════════════════════════════════════════════════════════════════════════════════════════════════════╝

┌─────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 1. rmsnorm_attn — Pre-Attention RMSNorm                                                                   │
├─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 计算: x_norm = x / sqrt(mean(x²) + eps) × weight                                                         │
│ 数据: 读写 (1, 4096) = 8KB 输入 + 4096×2B weight = 16KB                                                   │
│ Kernel: 3-4 个小 elementwise kernel (rsqrt, mul, cast)                                                    │
│ 瓶颈: LATENCY — 数据量极小,kernel launch overhead (~20us/kernel) 占主导                                     │
│ e2e ~76us ≈ 4 kernels × ~19us launch overhead                                                             │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 2. qkv_proj — Fused Q/K/V Linear Projection (1 GEMM)                                                     │
├─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 计算: [q,k,v] = x @ W_qkv,  shape: (1,4096) @ (4096,9216) = (1,9216)                                    │
│ 数据: 读 W_qkv = 4096×9216×2B = 75.5MB, 读 x = 8KB, 写 qkv = 18KB                                       │
│ FLOPs: 2×4096×9216 = 75.5M FLOPs (微不足道)                                                               │
│ Kernel: 1 个 sm90_xmma_gemm (Tensor Core GEMM)                                                           │
│ HBM: 65% — 读 75MB 权重用 35us → 2340 GB/s                                                                │
│ TC: 2.4% — 只有 75M FLOPs, H100 989T能力几乎空闲                                                          │
│ 瓶颈: MEM-bound — 本质是 matrix×vector, 算力需求 << 带宽需求                                                │
│ 算术强度: 75.5M FLOPs / 75.5MB = 1.0 FLOP/Byte (远低于H100的 295 FLOP/Byte 平衡点)                        │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 3. rope — Rotary Position Embedding                                                                       │
├─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 计算: 对 q (1,1,64,128) 和 k (1,1,4,128) 做旋转:                                                         │
│       x1,x2 = split(x); out = cat(x1*cos - x2*sin, x2*cos + x1*sin)                                     │
│ 数据: q=16KB, k=1KB, cos/sin=128B 预计算                                                                  │
│ Kernel: ~14 个小 elementwise kernel (split, mul, sub, cat, view, copy...)                                 │
│ 瓶颈: LATENCY — 数据量 <20KB, 但 PyTorch eager mode 产生大量零碎 kernel                                    │
│ e2e ~131us ≈ 14 kernels × ~9us — 最大的时间浪费点                                                          │
│ 优化建议: 用 fused RoPE kernel (如 flash_attn.layers.rotary) 可压缩到 1 kernel ~5us                        │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 4. attn — FlashAttention-2 Decode (flash_attn_with_kvcache)                                               │
├─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 计算: softmax(Q @ K^T / sqrt(d)) @ V,  Q:(1,1,64,128), KV_cache:(1,S,4,128)                              │
│       GQA: 64 Q heads 共享 4 KV heads (每 16 个 Q head 共享 1 个 KV head)                                  │
│ 数据: 读 KV cache = 2 × S × 4 × 128 × 2B                                                                 │
│       S=1K:  1MB    S=4K:  4MB    S=16K: 16MB   S=64K: 64MB                                               │
│ Kernel: 2 个 (flash_fwd_splitkv_kernel + flash_fwd_splitkv_combine_kernel)                                │
│ HBM: S=1K→4%, S=64K→15% — KV cache 小时带宽利用极低                                                       │
│ TC: <0.5% — decode 的 attention 是 (1,128)×(S,128), 不是大矩阵乘                                          │
│ 瓶颈: S≤16K LATENCY (KV cache <16MB, kernel launch+overhead 主导)                                          │
│       S=64K 开始 MEM-bound (KV cache=64MB, 读取开始占时间)                                                  │
│ 注意: ncu 35us vs e2e 115us(S=64K) 差异因为 ncu 只测 kernel 执行时间,                                      │
│       e2e 包含 event record overhead 和 kernel 排队等待                                                     │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 5. o_proj — Output Projection (1 GEMM)                                                                    │
├─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 计算: out = attn_out @ W_o,  shape: (1,8192) @ (8192,4096) = (1,4096)                                    │
│ 数据: 读 W_o = 8192×4096×2B = 67.1MB                                                                      │
│ FLOPs: 2×8192×4096 = 67.1M FLOPs                                                                         │
│ Kernel: 1 个 cuBLAS GEMM (非 Tensor Core 命名但实际用 TC)                                                  │
│ HBM: 68% → 2400 GB/s                                                                                      │
│ SM: 17% — cuBLAS 路径比 sm90_xmma 的 SM 利用率更高 (不同调度策略)                                           │
│ 瓶颈: MEM-bound — 算术强度 1.0 FLOP/Byte                                                                  │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 6. rmsnorm_mlp — Pre-MLP RMSNorm                                                                         │
├─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 同 rmsnorm_attn, 对残差连接后的 hidden state 做归一化                                                      │
│ 输入: residual = x + o_proj_out, shape (1, 4096)                                                          │
│ 瓶颈: LATENCY — 同上                                                                                      │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 7. gate_up_proj — Fused Gate+Up MLP Projection (1 GEMM) ★ 最大的 GEMM                                    │
├─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 计算: [gate, up] = h @ W_gate_up,  shape: (1,4096) @ (4096,28672) = (1,28672)                            │
│       SwiGLU MLP: gate 和 up 各 14336 维,拼成一个 GEMM                                                    │
│ 数据: 读 W_gate_up = 4096×28672×2B = 235MB — 单层最大的权重矩阵                                            │
│ FLOPs: 2×4096×28672 = 235M FLOPs                                                                         │
│ Kernel: 1 个 sm90_xmma_gemm (Tensor Core)                                                                │
│ HBM: 83% → 2795 GB/s — 所有 GEMM 中利用率最高 (矩阵越大, 带宽利用越好)                                     │
│ TC: 4.5% — 最高但仍很低                                                                                   │
│ 瓶颈: MEM-bound — 算术强度 1.0 FLOP/Byte                                                                  │
│ 耗时最长 (85us) 因为权重最大                                                                                │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 8. silu_mul — SiLU Activation × Gate                                                                      │
├─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 计算: hidden = SiLU(gate) × up = (gate / (1+exp(-gate))) × up                                            │
│ 数据: 读写 gate + up 各 (1,14336)×2B = 57KB                                                               │
│ Kernel: 2-3 个 elementwise kernel                                                                         │
│ 瓶颈: LATENCY — 57KB 数据量太小                                                                            │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 9. down_proj — MLP Down Projection (1 GEMM)                                                              │
├─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 计算: out = hidden @ W_down,  shape: (1,14336) @ (14336,4096) = (1,4096)                                 │
│ 数据: 读 W_down = 14336×4096×2B = 117.4MB                                                                 │
│ FLOPs: 2×14336×4096 = 117.4M FLOPs                                                                       │
│ Kernel: 1 个 cuBLAS GEMM                                                                                  │
│ HBM: 77% → 2674 GB/s                                                                                      │
│ SM: 17% — cuBLAS 路径                                                                                     │
│ 瓶颈: MEM-bound — 算术强度 1.0 FLOP/Byte                                                                  │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 10. residual — Residual Connections (×2)                                                                  │
├─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 计算: x = x + proj_out (element-wise add, 做两次: attention 后 + MLP 后)                                   │
│ 数据: 读写 (1,4096)×2B = 8KB × 2                                                                          │
│ 瓶颈: LATENCY — 最简单的操作, ~6us/次                                                                      │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────────┘

║  总结: Decode (B=1) 的性能特征                                                                              ║
╠══════════════════════════════════════════════════════════════════════════════════════════════════════════════╣
║                                                                                                            ║
║  1. 所有 GEMM 的算术强度 = 1.0 FLOP/Byte (matrix × vector)                                                ║
║     H100 平衡点 = 989T / 3.35TB = 295 FLOP/Byte                                                           ║
║     → 算术强度比平衡点低 295 倍 → Tensor Core 空闲 95%+                                                     ║
║                                                                                                            ║
║  2. 时间构成 (以 S=4096 为例):                                                                              ║
║     GEMM 权重读取 (qkv+o+gu+down):  ~496 MB / 3350 GB/s = ~148us (理论下限)                                ║
║     ncu 实测 GEMM 总时间:            196us (kernel overhead ~32%)                                           ║
║     e2e 实测 layer 总时间:           712us                                                                  ║
║     → 非 GEMM 开销 (norm+rope+attn+silu+residual+launch): 516us = 72% !!!                                 ║
║                                                                                                            ║
║  3. 最大优化空间:                                                                                           ║
║     a) Kernel fusion: 把 14 个 RoPE kernel 融合成 1 个 → 省 ~120us                                         ║
║     b) RMSNorm fusion: 把 3-4 个 norm kernel 融合成 1 个 → 省 ~120us                                       ║
║     c) Persistent kernel / CUDA Graph: 消除 kernel launch overhead                                         ║
║     d) Batch decode (B>1): 把 matrix×vector 变成 matrix×matrix → 提升算术强度                               ║
